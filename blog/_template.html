Designing a reliable batch ETL pipeline

    Why pipelines fail

    Most pipeline incidents come from small assumptions: an unexpected null, a column that changed type, or a schema that drifted silently. Writing down those assumptions is the first step to reliability.

    Tip
    Validate the contract before the transformation, not after.

    A small data contract

    Start with an explicit expectation for each column: type, allowed nulls and value ranges. A contract turns a silent failure into a loud, actionable error.

    python 
    import pandas as pd

def validate(df: pd.DataFrame) -> pd.DataFrame:
    assert df["order_id"].notna().all(), "order_id must be present"
    assert df["order_id"].is_unique, "order_id must be unique"
    df["created_at"] = pd.to_datetime(df["created_at"], errors="raise")
    return df

    Load idempotently

    Loading should be safe to re-run. Upserts on a stable key, partitioned writes, or replace-by-partition all beat appending blindly.

    Test with real shapes

    Use a sample of production data in tests. Synthetic data rarely reproduces the edge cases that break a pipeline.

    Next steps

    Add observability: row counts, freshness and a schema fingerprint. Alert on changes, not just failures.

    لماذا تفشل خطوط البيانات؟

    معظم أعطال خطوط البيانات تأتي من افتراضات صغيرة: قيمة فارغة غير متوقعة، أو تغيّر نوع عمود، أو انحراف صامت في المخطط. كتابة هذه الافتراضات صراحةً هي الخطوة الأولى نحو الموثوقية.

    نصيحة
    تحقق من العقد قبل التحويل، لا بعده.

    عقد بيانات صغير

    ابدأ بتوقّع صريح لكل عمود: النوع، والقيم الفارغة المسموحة، ونطاق القيم. العقد يحوّل الفشل الصامت إلى خطأ واضح وقابل للتصرف.

    python 
    import pandas as pd

def validate(df: pd.DataFrame) -> pd.DataFrame:
    assert df["order_id"].notna().all()
    assert df["order_id"].is_unique
    df["created_at"] = pd.to_datetime(df["created_at"])
    return df

    تحميل آمن للتكرار

    يجب أن يكون التحميل آمناً عند إعادة التشغيل. عمليات الإدراج المحدّث (upsert) على مفتاح ثابت، أو الكتابة حسب الأقسام، أفضل من الإضافة العشوائية.

    الخطوات التالية

    أضف المراقبة: عدد الصفوف، وحداثة البيانات، وبصمة المخطط. ونبّه عند التغيّر، لا عند الفشل فقط.
